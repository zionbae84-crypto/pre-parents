# 랜딩페이지 단계 카드 UI 개선 — 설계서

## 배경 및 목적

랜딩페이지의 "어떤 단계에 계신가요?" 5단계 카드 섹션이 현재는 텍스트만 있는 밋밋한 사각 버튼이다. 각 단계를 더 명확하고 따뜻하게 전달하기 위해 서수 라벨을 추가하고, 각 단계를 상징하는 "행복한 가정의 모습" 라인아트 아이콘을 넣어 살짝 움직이는 애니메이션을 적용한다.

## 변경 범위

`app/page.tsx`의 `STAGES` 섹션(현재 `app/page.tsx:3-9`, `39-49`)만 수정한다. 다른 페이지·컴포넌트는 영향받지 않는다.

## 라벨 텍스트

각 카드는 두 줄로 표시한다: 작은 서수 텍스트(위) + 굵은 단계명(아래).

| slug | 서수 텍스트 | 단계명 |
|---|---|---|
| 임신준비 | 첫 단계 | 임신준비 단계 |
| 임신중 | 두번째 단계 | 임신중 단계 |
| 출생출산 | 세번째 단계 | 출생·출산 단계 |
| 영유아기 | 네번째 단계 | 영유아기 단계 |
| 유아 | 다섯번째 단계 | 유아 단계 |

## 아이콘

각 단계를 상징하는 "가정의 모습"을 코랄/브라운 톤 얇은 선(stroke)의 인라인 SVG 라인아트로 통일된 스타일로 그린다. 외부 아이콘 라이브러리나 이미지 파일에 의존하지 않는다.

- 임신준비: 손을 맞잡은 두 사람 실루엣
- 임신중: 배가 부른 부모 옆에서 배를 쓰다듬는 파트너
- 출생·출산: 포대기에 싸인 아기를 안은 두 사람
- 영유아기: 유모차를 미는 부모
- 유아: 아이와 손잡고 걷는 부모

각 아이콘은 `components/ui/StageIcon.tsx`에 5개의 이름 붙은 SVG 컴포넌트(또는 하나의 컴포넌트가 `stage` prop을 받아 분기)로 구현하고, `app/page.tsx`에서 가져다 쓴다. `viewBox`와 `stroke-width`를 통일해 시각적 일관성을 유지한다.

## 애니메이션

각 아이콘에 2~3초 주기로 위아래로 살짝(수 px) 떠오르는(bobbing) `@keyframes float` CSS 애니메이션을 반복 적용한다. `app/globals.css`에 키프레임을 추가하고 `animate-float` 유틸리티 클래스로 노출한다(Tailwind v4 `@theme`의 애니메이션 확장 없이, 순수 CSS `@keyframes` + 커스텀 클래스로 충분).

카드 hover 시 기존 테두리/텍스트 코랄 강조 효과는 그대로 유지한다. `prefers-reduced-motion: reduce`인 사용자에게는 애니메이션을 끈다(접근성).

## 데이터 구조 변경

`app/page.tsx`의 `STAGES` 배열을 아래와 같이 확장한다:

```ts
const STAGES = [
  { slug: "임신준비", ordinal: "첫 단계", label: "임신준비 단계", Icon: HoldingHandsIcon },
  { slug: "임신중", ordinal: "두번째 단계", label: "임신중 단계", Icon: PregnantBellyIcon },
  { slug: "출생출산", ordinal: "세번째 단계", label: "출생·출산 단계", Icon: NewbornIcon },
  { slug: "영유아기", ordinal: "네번째 단계", label: "영유아기 단계", Icon: StrollerIcon },
  { slug: "유아", ordinal: "다섯번째 단계", label: "유아 단계", Icon: ToddlerWalkIcon },
] as const;
```

## 테스트 방침

순수 시각적 UI 변경이라 자동화 테스트 대상은 없다(기존 프로젝트 방침과 동일 — UI는 브라우저 수동 확인). `npm run build`로 타입/컴파일 오류 없음을 확인하고, 브라우저에서 5개 카드의 라벨·아이콘·애니메이션·hover 효과·`prefers-reduced-motion` 동작을 육안으로 검증한다.
