# 검색 폼(SearchForm) 개선 설계

## 배경

`/search` 페이지 사이드바의 검색 폼(`components/search/SearchForm.tsx`)이 나머지 UI와 비교해 어색하다는 피드백을 받았다. 문제는 크게 네 가지다.

1. 입력 필드 폭이 제각각(select 기본폭, `w-32`, `w-48`)이라 통일감이 없다.
2. "부모 나이" 라벨이 실제로는 산모/여성 나이를 의미하는 데이터인데도 중립적인 이름을 쓰고 있다.
3. "가구원수" 필드가 왜 필요한지 사용자에게 설명되지 않는다.
4. 가구월소득 입력값이 숫자 그대로 표시돼(`4000000`) 자릿수를 읽기 어렵다.

## 1. `parentAge` → `motherAge` 전체 리네임

현재 시드 데이터(`lib/data/programs.ts`)에서 구조화된 나이 필드(`parentAgeMin/Max`)를 쓰는 항목은 2개뿐이며, 둘 다 실제로는 산모/여성 나이를 의미한다(`gov-teen-mother-medical-expense`의 "청소년산모", `seoul-korean-medicine-infertility-treatment`의 "여성 만 45세 이하"). 따라서 코드베이스 전반에 걸쳐 `parentAge` 계열 이름을 `motherAge`로 통일한다.

변경 대상:

| 파일 | 변경 내용 |
|---|---|
| `components/search/SearchForm.tsx` | `parentAge` state → `motherAge`, 라벨 "부모 나이" → "엄마 나이", `SearchFormValues.parentAge` → `motherAge` |
| `lib/matching.ts` | `SearchCriteria.parentAge` → `motherAge`, `matchesParentAge` → `matchesMotherAge` 함수명 및 내부 로직(참조하는 `parentAgeMin/Max`) |
| `lib/schemas.ts` | `eligibilitySchema`의 `parentAgeMin`/`parentAgeMax` → `motherAgeMin`/`motherAgeMax` |
| `lib/data/programs.ts` | 위 2개 항목의 `parentAgeMax` 필드명 변경 (값은 그대로) |
| `app/search/page.tsx` | `handleSubmit`에서 `SearchCriteria` 생성 시 필드명 반영 |
| `components/programs/ProgramCard.tsx` | `needsEligibilityCheck`의 구조분해 필드명 반영 |
| 관련 테스트 파일 | `lib/matching.test.ts` 등에서 필드명·함수명 갱신 |

`householdSize`는 이름 변경 대상이 아니다(아래 2번 참조).

## 2. 가구원수 필드: 유지 + 설명 힌트

`householdSize`는 `lib/income.ts`의 `calculateIncomePercent`가 기준중위소득 대비 소득 비율을 계산하는 데 필수 입력값이며, 이 비율이 여러 사업의 `incomePercentMax` 자격 조건(예: 산모·신생아 건강관리 150%, 서울형 가사서비스 180%)을 가른다. 따라서 필드는 제거하지 않고 유지하되, 라벨 아래에 작은 보조 설명을 추가해 존재 이유를 알린다.

```
가구원수
[가구원수는 소득 기준(중위소득 %) 계산에 사용돼요]  ← text-[13px] text-brown/60
[입력창]
```

## 3. 가구월소득 천단위 콤마 표시

입력 타입을 `type="number"`에서 `type="text"` + `inputMode="numeric"`으로 바꾼다. 내부 state(`monthlyIncome: number`)는 그대로 순수 숫자를 유지하고, 화면에 표시되는 값만 `toLocaleString('ko-KR')`로 콤마를 포맷한다. `onChange`에서는 입력값의 콤마와 숫자 이외 문자를 제거한 뒤 `Number()`로 파싱해 state에 반영한다. 빈 문자열 입력은 `0`으로 처리한다.

## 4. 시각적 통일성 정리

- 거주지 select 2개, 엄마 나이/가구원수/소득 input 모두 `w-full`로 통일한다. 사이드바가 좁은 컬럼이므로 필드는 기본적으로 한 줄씩 세로로 쌓되, 엄마 나이와 가구원수는 `grid grid-cols-2 gap-3`로 나란히 배치해 공간을 절약한다.
- "현재 상태" 라디오 버튼(임신 준비중/임신중/출산완료)을 네이티브 `<input type="radio">` 대신 앱의 필박스 버튼 스타일로 바꾼다: 미선택 시 `rounded-button border-2 border-brown/20 px-4 py-2 text-brown`, 선택 시 `bg-coral text-white border-coral`. 클릭 시 `onClick`으로 상태를 전환하는 버튼 그룹으로 구현한다(라디오의 접근성을 유지하기 위해 `role="radiogroup"`과 각 버튼에 `aria-pressed`를 부여).
- 라벨 폰트를 `text-[15px] font-bold text-brown`으로 명시해 카드 제목(`text-[19px]`, `font-display`)과 시각적으로 구분되도록 한다.
- 폼 전체 컨테이너는 `border-2 border-brown/10` 테두리를 유지하되 필드 간 간격을 `gap-6`에서 `gap-5`로 줄여 더 조밀하게 만든다.

## 영향받지 않는 범위

- `householdSize`, `monthlyIncome`의 데이터 타입과 매칭 로직(`matchesIncome`)은 변경하지 않는다.
- 다른 페이지(`/programs` 등)의 컴포넌트는 이 변경의 영향을 받지 않는다.
- 백엔드/데이터 스키마의 다른 필드는 변경하지 않는다.

## 테스트 방침

- `lib/matching.test.ts`: `matchesParentAge` → `matchesMotherAge` 이름 변경 및 관련 테스트 케이스의 필드명 갱신.
- UI(폼 레이아웃, 콤마 포맷팅, 라디오→버튼 전환)는 프로젝트 정책에 따라 자동화 테스트를 작성하지 않고 브라우저에서 수동 검증한다.
